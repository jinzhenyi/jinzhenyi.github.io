📋 1. Issue 表单模板（Friend Request Form）

文件：.github/ISSUE_TEMPLATE/friend_request.yml

作用：定义用户在创建 Issue 时看到的表单，规范数据输入格式。

关键配置：

· title: "[友链申请] " → 自动填充 Issue 标题，用户无需手动输入。
· labels: ["友链申请"] → 创建时自动添加标签，作为工作流的触发条件。
· 必填字段：站点名称、站点主页、友链页面。
· 可选字段：头像链接、一句话描述。
· 确认事项：必须勾选（已添加本站链接）。

数据流向：用户提交后，表单内容以 Markdown 格式存储在 Issue Body 中，供后续脚本解析。

⚙️ 2. GitHub Actions 触发机制

文件：.github/workflows/add-friend.yml

```yaml
on:
  issues:
    types: [labeled, opened]
```

触发条件：

1. opened：创建新 Issue 时触发。
2. labeled：为 Issue 添加标签时触发（防止模板标签未自动生效）。

Job 条件：

```yaml
if: contains(github.event.issue.labels.*.name, '友链申请')
```

只有当 Issue 包含 友链申请 标签时，才执行后续操作。

权限设置：

```yaml
permissions:
  issues: write   # 允许添加标签/评论/关闭 Issue
  contents: write # 允许通过 API 更新文件
```

3.3 审核流程（按顺序）

```
┌─────────────────────────────────────────────────────────────────┐
│                    审核流程图                                  │
├─────────────────────────────────────────────────────────────────┤
│  Step 1: 必填校验                                             │
│  ├─ 站点名称 → 缺失则拒绝                                    │
│  ├─ 站点主页 → 缺失则拒绝                                    │
│  └─ 友链页面 → 缺失则拒绝                                    │
├─────────────────────────────────────────────────────────────────┤
│  Step 2: URL 格式校验                                        │
│  └─ 必须以 http:// 或 https:// 开头 → 否则拒绝              │
├─────────────────────────────────────────────────────────────────┤
│  Step 3: Ping 检测（链接可访问性）                           │
│  ├─ 站点主页 → 不可达则打标签[链接不通]并拒绝              │
│  ├─ 友链页面 → 不可达则打标签[链接不通]并拒绝              │
│  └─ 头像链接 → 不可达则打标签[头像链接不通]并拒绝          │
│     （仅当用户填了头像且非空时检测）                         │
├─────────────────────────────────────────────────────────────────┤
│  Step 4: 反链检测                                           │
│  ├─ GET 请求用户提供的友链页面                              │
│  ├─ 搜索 MY_DOMAIN 是否存在                                 │
│  ├─ 存在 → 通过                                            │
│  └─ 不存在 → 打标签[返链未存在]并拒绝                      │
├─────────────────────────────────────────────────────────────────┤
│  Step 5: 去重检查                                           │
│  └─ 站点主页已在列表中 → 提示并关闭                        │
├─────────────────────────────────────────────────────────────────┤
│  Step 6: 写入 JSON（通过 GitHub API）                       │
│  ├─ 获取现有 _data/friends.json                             │
│  ├─ 追加新条目                                              │
│  └─ 通过 update_file / create_file 提交                    │
├─────────────────────────────────────────────────────────────────┤
│  Step 7: 成功标记                                           │
│  ├─ 打标签[审核通过]                                        │
│  ├─ 发布成功评论并 @ 用户                                   │
│  └─ 关闭 Issue                                              │
```

🏷️ 4. 标签系统

标签 触发条件 颜色
友链申请 自动添加 默认
链接不通 站点主页或友链页面不可访问 橙色
头像链接不通 头像链接不可访问（仅当填写时） 黄色
返链未存在 友链页面中未找到本站域名 红色
审核通过 所有检查通过 绿色

标签在脚本中自动创建（若不存在），并通过 issue.add_to_labels() 动态添加。

📧 6. 用户通知机制

```
审核成功时：
  Issue 评论：✅ 友链 `{name}` 已成功添加！
  发布者：github-actions[bot]
  触发：@ 用户 → GitHub 自动发送邮件通知

审核失败时：
  Issue 评论：❌ 具体失败原因
  同时打上对应标签 → 用户一眼可知失败原因
```

🔄 7. 完整数据流

```
用户提交 Issue
    → GitHub Actions 触发
    → Python 脚本解析表单
    → 循环执行：校验 → Ping → 反链 → 去重
    → 更新 _data/friends.json（GitHub API）
    → 打标签 + 评论 + 关闭 Issue
    → 博客重新构建 → 新友链出现在 /friends/ 页面
```

💡 9. 设计亮点

1. 无需人工干预：全流程自动化，从提交到上链完全自动。
2. 反链验证：确保双向链接，杜绝单方面添加。
3. 多级校验：必填 → 格式 → 可访问 → 反链 → 去重，层层把关。
4. 友好反馈：通过标签 + 评论 + @提及，用户清晰知晓审核结果。
5. 数据与展示分离：JSON 数据文件 + Markdown 页面，职责清晰。
6. GitHub API 更新：无需 Git 命令，更稳定可靠。
